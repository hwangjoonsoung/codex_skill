# /qna-summary — 세션 질문 정리 스킬

## 목적

**현재 세션에서 사용자가 던진 질문들**을 되돌아보고, 주제 단위로 묶어 각각을 별도의 markdown 파일로 정리한다. 나중에 다시 찾아보거나 지식으로 축적할 수 있도록 구조화된 문서를 남기는 것이 목표다.

## 핵심 원칙

1. **대상은 "사용자가 이 세션에서 한 질문"** 이다. 스킬 실행 이전까지 이 대화에서 사용자가 물어봤던 내용을 근거로 삼는다. 세션 밖 내용을 추측해 채우지 않는다.
2. **한 세션 = 여러 주제 가능**. 사용자가 서로 다른 주제로 여러 번 질문했을 수 있다. 주제끼리 연관될 수도, 완전히 별개일 수도 있다.
3. **주제 하나당 파일 하나**. 주제를 식별한 만큼 파일을 분리 생성한다.
4. **추측 금지**. 대화에 실제로 오간 내용만 정리한다. 불확실하면 그렇게 표기하고, 비워두기보다 "세션에서 다루지 않음"으로 명시한다.
## 진행 절차

### S1. 세션 질문 수집
현재 세션(이 대화)에서 사용자가 한 질문·요청을 시간 순으로 훑어 목록화한다. 각 질문에 대해 어떤 답변/결론이 오갔는지도 함께 기억해 둔다.

### S2. 주제 분리
수집한 질문들을 의미 단위로 그룹화한다.
- 같은 대상/맥락을 다루면 한 주제로 묶는다.
- 맥락이 바뀌면 새 주제로 분리한다.
- 애매하면 사용자에게 "이 두 건을 한 주제로 볼지 나눌지" 확인한다.
- 각 주제에 대해 **주제 분류 태그**를 부여한다: 운영 / 개발 / 디자인 / ai 등. **다중 선택 가능** (예: `개발, ai`).
- 각 주제에 대해 **대주제(핵심 대상)** 를 하나 뽑는다. 질문이 실제로 무엇에 대한 것인지를 나타내는 고유명사/기술명 수준의 키워드다.
    - 예: nginx 설정을 물었으면 `nginx`, Redis TTL 을 물었으면 `redis`, 이 스킬 자체를 고쳤으면 `claude-skills`.
    - 영문 소문자 kebab-case 로 정규화한다(한글 대상이면 대표 영문 키워드로 변환).
    - 대주제가 명확히 잡히지 않으면 추측하지 말고 사용자에게 무엇으로 묶을지 확인한다.

### S3. 주제별 파일 작성
주제마다 아래 형식으로 markdown 파일을 하나씩 작성한다.

**형식**

파일명이 곧 제목이므로 **본문에 `# {제목}` H1 을 다시 쓰지 않는다**(Obsidian 이 파일명을 제목으로 표시 → 중복 방지). 문서는 해시태그 줄로 시작한다.

```markdown
{#해시태그 나열 — 문서 첫 줄}

## 주제
{운영 / 개발 / 디자인 / ai 등, 다중 선택 시 쉼표로 나열}
 
## 개요
{이 주제에서 무엇을 물었고 무엇을 다뤘는지 2~4줄 요약}
 
## 내용 (정리)
{실제로 오간 질문과 답변·논의를 구조화해 정리. 필요 시 소제목/목록/코드블록 사용}
 
## 결론
{최종적으로 도출된 결론·결정·다음 액션}
```

**태그 규칙**
- 위치는 **문서 맨 첫 줄**(H1 없이 태그부터 시작). 별도 `## 태그` 섹션을 만들지 않는다.
- Obsidian 에서 바로 검색되도록 `#` 를 붙인 해시태그로 나열한다(공백 구분, 한 줄).
- 반드시 포함: 분류 태그(`#develop` 등)와 대주제(`#nginx` 등).
- 여기에 더해 **세션에서 실제로 다룬 관련 키워드**를 태그로 추가한다. 예: nginx 리버스 프록시 + SSL 질문이면
  `#develop #nginx #reverse-proxy #ssl #config`
- 태그는 영문 소문자 kebab-case, 3~7개 수준으로 유지한다. 대화에 나오지 않은 키워드를 추측해 넣지 않는다.
- 고유명사/제품명은 통용되는 표기를 그대로 쓴다(`#spring-boot`, `#mysql`, `#redis`).

**파일 경로 / 이름**

경로는 고정이 아니라 **질문 내용에 따라 스킬이 스스로 결정**한다.

```
~/Desktop/obsidan/{분류}/{대주제}/{주제}.md
```

- **베이스**: `~/Desktop/obsidan/` (고정)
- **{분류}**: S2 에서 부여한 주제 분류 태그를 영문 디렉토리명으로 매핑한다. 태그가 여러 개면 **가장 대표적인 것 하나**만 경로에 쓴다(나머지는 문서 본문 `## 주제` 에 모두 남긴다).

    | 태그 | 디렉토리 |
    |---|---|
    | 개발 | `develop` |
    | 운영 | `operation` |
    | 디자인 | `design` |
    | ai | `ai` |
    | 그 외 | 해당 태그의 간결한 영문 소문자 이름 |

- **{대주제}**: S2 에서 뽑은 대주제 슬러그. 예: `nginx`, `redis`, `spring`.
    - 예시: nginx 에 대해 물었고 분류가 `개발` 이면 → `~/Desktop/obsidan/develop/nginx/`
- **파일명**: **주제(제목) 그 자체**. 날짜나 부가 정보를 붙이지 않는다.
    - 파일명이 곧 문서 제목이다(본문에 H1 을 중복해 넣지 않는다).
    - 예: `리버스 프록시 설정.md`, `Redis TTL 전략.md`
    - 한글 제목은 그대로 쓰되, 파일명에 쓸 수 없는 문자(`/ \ : * ? " < > |`)는 제거하거나 `-` 로 치환한다.
    - 동일 파일이 이미 있으면 덮어쓰지 말고 뒤에 ` -2`, ` -3` 을 붙인다.

> 대상 디렉토리가 없으면 `mkdir -p` 로 먼저 생성한다(중간 경로 포함).
> 이미 같은 대주제 디렉토리가 다른 이름으로 존재하는지(`nginx` vs `nginx-config` 등) 저장 전에 베이스 디렉토리를 한 번 확인하고, 기존 디렉토리가 있으면 새로 만들지 말고 재사용한다.

### S4. git add / commit / push (자동)

파일 작성이 끝나면 **볼트 저장소(`~/Desktop/obsidan`)에 대해** 자동으로 커밋·푸시한다. 사용자에게 별도로 확인받지 않는다(이 스킬 실행 자체가 승인이다).

```bash
git -C ~/Desktop/obsidan add -A
git -C ~/Desktop/obsidan commit -m "docs(qna): {주제1}, {주제2} 정리"
git -C ~/Desktop/obsidan push
```

규칙:
- **작업 범위는 `~/Desktop/obsidan` 하나뿐**이다. 다른 저장소(현재 작업 디렉토리 포함)에는 절대 `git add/commit/push` 하지 않는다. 반드시 `git -C ~/Desktop/obsidan` 형태로 대상을 명시한다.
- 커밋 메시지: `docs(qna): {이번에 생성한 주제들 나열} 정리`. 파일이 여러 개면 쉼표로 나열하고, 3개를 넘으면 `외 N건` 으로 줄인다.
- `git -C ~/Desktop/obsidan status --porcelain` 결과가 비어 있으면(변경 없음) 커밋·푸시를 건너뛰고 그대로 보고한다.
- push 가 실패하면(rebase 필요/인증 오류 등) **임의로 force push 하거나 히스토리를 고치지 않는다.** 커밋까지는 남긴 채 실패 내용을 그대로 사용자에게 보고한다.
- `~/Desktop/obsidan` 이 git 저장소가 아니면 `git init` 하지 말고, 파일 저장까지만 완료했다고 보고한다.

### S5. 결과 보고
생성한 파일 목록(경로 + 제목 + 주제 분류 + 해시태그)을 사용자에게 표로 보고하고, S4 의 커밋 해시·푸시 결과(또는 스킵/실패 사유)를 한 줄 덧붙인다.

## 권한

이 스킬은 frontmatter `allowed-tools` 로 **필요한 명령만, 이 스킬 실행 중에만** 허용된다. 전역 설정(`settings.json`)에 권한을 추가하지 않는다.

허용 범위:
- `Write` / `Read` / `Glob` — 문서 작성 및 기존 문서 확인
- `mkdir -p ~/Desktop/obsidan/*`, `ls ~/Desktop/obsidan*` — 경로 생성/확인
- `git -C ~/Desktop/obsidan` 의 `status` / `add` / `commit` / `push` / `rev-parse` / `log`

허용되지 않는 것(추가하지 말 것):
- 볼트 이외 저장소에 대한 git 명령, `git -C` 없는 `git` 명령
- `push --force`, `reset`, `rebase`, `clean` 등 히스토리·작업트리 파괴 명령
- `rm` 등 파일 삭제 명령

## 참고
- 파일 작성은 `Write` 도구로 새로 생성한다. 동일 파일이 이미 있으면 덮어쓰지 말고 파일명에 번호를 붙여 새로 만든다.
- 정리 언어는 한국어를 기본으로 한다(질문이 다른 언어면 그 맥락을 존중).
